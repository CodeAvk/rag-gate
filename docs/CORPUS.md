# Test corpora: synthetic-v1 and synthetic-v2

Generated by `src/corpus/synthetic.ts` (`npm run corpus [seed] [v1|v2]`). Output goes to `data/corpus/synthetic-<version>-seed<seed>/` (git-ignored); the same seed always produces the same files. A unit test pins a fingerprint of v1, so v1 cannot change silently while v2 evolves.

## Licence

All text is generated by this repository. No third-party text is used, so no external licence applies. This also keeps the free-tier rule: only synthetic text is sent to the Gemini API.

## Contents (seed 1)

| Item | Count |
|---|---|
| Fictional products | 12 (6 families x models "4" and "5") |
| Fact passages | 84 (7 facts per product: warranty, battery life, weight, wireless range, operating temperature, return window, recharge time) |
| Distractor passages | 12 (one per product; repeats question keywords, contains no answer) |
| Questions | 168: one **literal** and one **paraphrased** question per fact |
| Split | 84 dev, 84 held-out, balanced within each style |

Each question records its gold passage id and the exact answer value.

## How it is meant to test retrieval

- **Literal** questions reuse the passage's wording (for example "How many grams does the Kestrel 4 weigh without accessories?"). Keyword search (BM25) should do well on these.
- **Paraphrased** questions avoid that wording ("How heavy is the Kestrel 4 to carry around?"). A unit test enforces that each paraphrase shares at most one content word with its passage, ignoring the product name; in seed 1 most share none. Literal questions must share at least two.
- **Near-identical names** ("Kestrel 4" and "Kestrel 5") require retrieval to pick the right product, not only the right topic.
- **Distractors** contain words such as warranty, battery and wireless, to trap keyword matching.

## synthetic-v2: the harder set (added 2026-11-08)

v1 put Gemini embeddings at 1.000 on every metric, which leaves no room to detect a regression. v2 (`src/corpus/synthetic-v2.ts`) changes three things:

| | v1 | v2 |
|---|---|---|
| Products | 12 (models "4", "5") | 24 (models "4", "4 Pro", "5", "5 Lite") |
| Wordings | one per fact | two per passage and two per question, drawn per product |
| Passages | one sentence | one or two sentences that also mention neighbouring topics (a warranty passage mentions battery wear and returns) |
| Size (seed 1) | 96 passages, 168 questions | 192 passages, 336 questions (168 dev, 168 held-out) |

Literal questions reuse the wording of their own passage (at least 3 shared content words in seed 1); paraphrases share at most one, as in v1. Both rules are enforced by tests for both sets.

## Caveats, stated plainly

- I wrote the templates myself, knowing that embeddings should handle paraphrase better than BM25. The set is therefore built to expose that difference; it is a stress test, not an estimate of real-world performance.
- Paraphrases still contain the product name, which BM25 can match. That is realistic, but it means BM25 can narrow to the right product and only has to guess the fact.
- v1's templates are fixed, one sentence shape per fact. v2 has two per fact, which is better but still a small, author-written template bank.
- v2 was written after seeing v1's results, to make the test harder. That is the purpose of a harder set, but it was not designed blind.
- The held-out split is fixed by the seed and must be used once, for the final Gate 1 comparison only.
